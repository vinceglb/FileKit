`write()` and `writeString()` replace the content of a file, creating it if needed. For large or incremental writes, stream with `sink()`.

## Usage

```kotlin nonWebMain
val file = FileKit.filesDir / "notes.txt"

file.writeString("Hello, FileKit!")
file.write("Hello again".encodeToByteArray())
```

Both are suspend functions that switch to `Dispatchers.IO`. The parent directory must exist: create it first with [`createDirectories()`](/core/file-operations#create-directories). Failures throw `kotlinx.io.IOException` or `FileKitException`.

<Note>
These functions are not declared in `commonMain`. Call them from `nonWebMain` or a platform source set. The web has separate, experimental versions for the origin private file system: see [Write on the web](#write-on-the-web).
</Note>

## Copy another file's content

`write` also takes a `PlatformFile` and streams its content into the destination, without loading it into memory:

```kotlin nonWebMain
val destination = FileKit.filesDir / "copy.pdf"
destination write pickedFile
```

This works when the source size is unknown, as with some Android `content://` files. It throws if the source is a directory or the same file as the destination. To copy into a folder or copy a whole tree, see [File operations](/core/file-operations#copy-a-file).

## Stream with a sink

`sink()` returns a kotlinx-io `RawSink`. Pass `append = true` to add to the end of the file instead of replacing it:

```kotlin nonWebMain
suspend fun appendLog(file: PlatformFile, line: String) = withContext(Dispatchers.IO) {
    file.sink(append = true).buffered().use { sink ->
        sink.writeString("$line\n")
    }
}
```

`sink()` does blocking I/O: call it on `Dispatchers.IO`, and close it with `use` so the data is flushed.

## Write on the web

Browsers don't let a page write to the user's files. On JS and Wasm you have two options:

- Give the user a file with `FileKit.download(bytes, fileName)`: see [Download files](/core/web#download-files).
- Store files in the browser's private storage with the experimental origin private file system API, which provides its own `write`, `writeString`, and `delete`: see [Files on the web](/core/web#store-files-in-the-origin-private-file-system).

## Platform notes

| Platform | Behavior |
| --- | --- |
| Android | Writing to a `content://` file truncates it first (`append = false`), including on providers such as Google Drive. A file you create with `/` inside a picked folder is created as a new document. |
| iOS, macOS | Security-scoped access is started and stopped for you, also for `sink()` until you close it. |
| Web | Only origin private file system files can be written. Writing to a picked file throws. |

FileKit Core provides a consistent API for writing files across all platforms. The `PlatformFile` class offers multiple methods to write data to files, from simple strings to binary data and streaming operations.

## Writing from ByteArray

The most common way to write data to a file is using the `write()` infix function with a `ByteArray`:

```kotlin
val file = PlatformFile(FileKit.filesDir, "image.jpg")

// Write the bytes
file.write(bytes)
```

## Writing from String

You can also write a string to a file using the `writeString()` function:

```kotlin
val file = PlatformFile(FileKit.filesDir, "document.txt")

// Write the string
file.writeString("Hello, FileKit!")
```

## Using Sink

For more advanced use cases or when working with large files, you can use the `sink()` method:

```kotlin
fun writeLargeFile() {
    val file = PlatformFile("/path/to/large-file.dat")
    
    // Get a raw sink for the file (overwrites existing file)
    val sink = file.sink(append = false).buffered()
    
    // Use the sink to write in chunks
    sink.use { bufferedSink ->
        // Write a string
        bufferedSink.writeString("Line 1\n")
        
        // Write bytes
        val bytes = ByteArray(1024) { it.toByte() }
        bufferedSink.write(bytes)
    }

    // Copy from another source file (safe for unknown-size provider-backed files)
    val sourceFile = PlatformFile("/path/to/source.dat")
    sourceFile.copyTo(file)
}
```

<Note>
Some provider-backed files (for example, certain Android `content://` URIs) may not expose a reliable size ahead of time. Prefer `destination.write(sourceFile)` or `sourceFile.copyTo(destination)` for robust streaming copy behavior.
</Note>

## Appending to Files

To append data to an existing file instead of overwriting it, use the `append` parameter:

```kotlin
fun appendToFile() {
    val file = PlatformFile("/path/to/log.txt")
    
    // Get a sink that appends to the file
    val sink = file.sink(append = true).buffered()
    
    sink.use { bufferedSink ->
        bufferedSink.writeUtf8("New log entry: ${Clock.System.now()}\n")
    }
}
```

## Copying Files

You can easily copy the contents of one file to another using the `write` infix function with another `PlatformFile` or the `copyTo` function:

```kotlin
val sourceFile = PlatformFile("/path/to/source.txt")
val destinationFile = PlatformFile("/path/to/destination.txt")

// Method 1: Using write
destinationFile.write(sourceFile)

// Method 2: Using copyTo
sourceFile.copyTo(destinationFile)
```

If the `copyTo()` destination is a directory, FileKit copies into it using the source
file's name. Otherwise, the destination is the file to write. Existing destination
files are overwritten.

## Copying Files and Directories Recursively

Use `copyRecursively()` to copy a directory tree or a regular file on non-Web
targets. Its `target` is the final destination, including the destination filename
when copying a regular file.

For a directory, the target becomes the new root. The source directory's name is
not added to the destination:

```kotlin
val sourceDirectory = PlatformFile("/path/to/source")
val targetDirectory = PlatformFile("/path/to/backup")

// source/sub/report.txt becomes backup/sub/report.txt
sourceDirectory.copyRecursively(targetDirectory)
```

For a regular file, specify the complete destination path to keep or change its name:

```kotlin
val sourceFile = PlatformFile("/path/to/source/report.txt")
val targetFile = PlatformFile("/path/to/backup/renamed-report.txt")

// Creates a copy named renamed-report.txt; the source stays in place
sourceFile.copyRecursively(targetFile)
```

For filesystem paths, missing parent directories are created automatically. An empty
source directory also creates an empty target directory. If the target already
exists, it must have the same type as the source. A file cannot replace a directory,
and a directory cannot replace a file, including conflicts inside a copied tree.

### Existing Files

Existing directories are merged, preserving unrelated destination entries. The
`overwrite` parameter controls what happens to conflicting files:

| Value | Behavior |
| --- | --- |
| `false` (default) | Leaves the existing file unchanged, skips its source entry, and continues. |
| `true` | Replaces the existing destination file. |

```kotlin
// Merge the tree and replace conflicting destination files
sourceDirectory.copyRecursively(targetDirectory, overwrite = true)
```

### Copy Callbacks

Callbacks are optional and run synchronously when an event occurs:

| Callback | Argument | Called when |
| --- | --- | --- |
| `onFileSkipped` | Source entry | A source link is skipped, the source or target itself is a link, or a destination file exists with `overwrite = false`. |
| `onFileAdded` | Destination file | A new file has been successfully copied. |
| `onFileOverwritten` | Destination file | An existing file has been successfully replaced. |

Creating or merging directories does not invoke `onFileAdded` or
`onFileOverwritten`. Without `onFileSkipped`, skipped entries produce no notification.

```kotlin
sourceDirectory.copyRecursively(
    target = targetDirectory,
    overwrite = true,
    onFileSkipped = { source -> println("Skipped: ${source.path}") },
    onFileAdded = { destination -> println("Added: ${destination.path}") },
    onFileOverwritten = { destination -> println("Overwritten: ${destination.path}") },
)
```

A callback can throw to stop the copy. For example, reject any skipped entry:

```kotlin
sourceDirectory.copyRecursively(
    target = targetDirectory,
    onFileSkipped = { source ->
        throw IllegalStateException("Copy skipped: ${source.path}")
    },
)
```

### Errors and Platform Notes

Choose a target outside the source directory tree. Copying onto the source itself,
a detected descendant destination, and file/directory conflicts throw. Symbolic-link
source entries are skipped without following their targets. If the source or target
itself is a link, the whole operation is skipped. On Windows, this includes junctions
and other reparse points.

<Warning>
The first I/O, validation, or callback error stops the operation without rollback.
Files and directories already copied remain in the destination; a failed write may
also leave a partially written file. A successful return can still include skipped
entries when `overwrite = false` or links are encountered.
</Warning>

On Apple platforms, FileKit keeps security-scoped access to the source and target
active throughout the copy and releases it when the operation ends.

<Note>
Android document URI destinations depend on the current child-document creation and
parent resolution support. Providers with opaque document IDs are not fully supported:
creating nested destinations may fail, and directory ancestry cannot always be checked.
Resolving the source's relative path does not guarantee that its destination can be created.
This API is not available on JS/WASM targets.
</Note>

## Moving Files

You can move a file from one location to another using the `atomicMove` function:

```kotlin
val sourceFile = PlatformFile("/path/to/source.txt")
val destinationFile = PlatformFile("/path/to/destination.txt")

// Move the file
sourceFile.atomicMove(destinationFile)
```

## Deleting Files

FileKit also provides a method to delete files:

```kotlin
val file = PlatformFile(FileKit.cacheDir, "temporary.txt")

// Delete the file (throws if file doesn't exist)
file.delete()

// Or specify that the file doesn't need to exist
file.delete(mustExist = false)
```

To delete a directory and its contents, opt into recursive deletion:

```kotlin
val directory = PlatformFile(FileKit.cacheDir, "temporary-downloads")
directory.delete(recursively = true)
```

For filesystem paths, `recursively` defaults to `false`, so deleting a non-empty
directory fails unless you enable it. Symbolic links (including dangling links)
and Windows directory junctions are removed as links; their targets are left
untouched. Android document URIs continue to use the document provider's deletion
behavior.

## Creating Directories

Before writing to a file, you may need to ensure its parent directory exists:

```kotlin
val directory = PlatformFile(FileKit.filesDir, "reports/2023/q4")

// Create the directory and all parent directories if they don't exist
if (!directory.exists()) {
    directory.createDirectories()
}

// Now we can write to a file in this directory
val reportFile = directory / "summary.txt"
reportFile.writeString("Quarterly Report")
```

## Error Handling

When writing files, you should handle potential errors:

```kotlin
val file = PlatformFile(FileKit.filesDir, "document.txt")
val content = "Hello, FileKit!"

try {        
    file.writeString(content)
    println("File written successfully")
} catch (e: Exception) {
    println("Error writing file: ${e.message}")
}
```

## Example: Creating a Simple Logger

```kotlin
class SimpleLogger(private val logFile: PlatformFile) {
    fun log(message: String) {
        // Get current timestamp
        val timestamp = Clock.System.now()
        val logEntry = "[$timestamp] $message\n"

        // Append to log file
        val sink = logFile.sink(append = true).buffered()
        sink.use { it.writeString(logEntry) }
    }
}

// Usage
fun main() {
    val logger = SimpleLogger(PlatformFile(FileKit.filesDir, "app.log"))
    logger.log("Application started")
}
```

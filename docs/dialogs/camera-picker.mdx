Open the system camera to take a photo. FileKit writes the photo to a file and returns it as a `PlatformFile`. Call it from a source set that only includes Android and iOS, such as `mobileMain` (see [shared source sets](/platform-support#use-platform-specific-apis-from-shared-code)).

## Usage

<CodeGroup>

```kotlin Compose
val launcher = rememberCameraPickerLauncher(
    onError = { failure -> showError(failure.message) },
) { photo ->
    // photo is a PlatformFile, or null if the user cancelled
}

Button(onClick = { launcher.launch() }) {
    Text("Take a photo")
}
```

```kotlin Suspend API
val photo: PlatformFile? = FileKit.openCameraPicker()
```

</CodeGroup>

## Options

| Parameter | Values | Default | Where (Compose) | Notes |
| --- | --- | --- | --- | --- |
| `type` | `FileKitCameraType.Photo` | `Photo` | `launch()` | Video capture is not available yet. |
| `cameraFacing` | `System`, `Front`, `Back` | `System` | `launch()` | `System` lets the camera app choose. See the Android note below. |
| `destinationFile` | `PlatformFile` | `FileKit.cacheDir / "<random UUID>.jpg"` | `launch()` | Where the photo is written. |
| `openCameraSettings` | `FileKitOpenCameraSettings` | `createDefault()` | `rememberCameraPickerLauncher` | Android: `authority`. iOS: `presenter`. |

`FileKitOpenCameraSettings` has one property per platform:

| Property | Platform | Default | Effect |
| --- | --- | --- | --- |
| `authority` | Android | `${applicationId}.FileKitFileProvider` | FileProvider authority for a `destinationFile` outside `filesDir` and `cacheDir`. |
| `presenter` | iOS | `null` | `UIViewController` that presents the camera. When `null`, the suspend API presents from its own window above your app and the Compose launcher uses the current `LocalUIViewController`. |

## Keep the photo

The default destination is in the cache directory, which the system can clear. To keep the photo, write it to `FileKit.filesDir` directly:

```kotlin
val photo = FileKit.openCameraPicker(
    destinationFile = FileKit.filesDir / "profile.jpg",
)
```

Files in `FileKit.filesDir` and `FileKit.cacheDir` need no Android setup. For any other directory, see [Android setup](#android-setup).

## Platform notes

| Platform | Behavior |
| --- | --- |
| Android | Launches the device camera app with `ACTION_IMAGE_CAPTURE`. If your manifest declares `android.permission.CAMERA`, FileKit requests it before opening the camera, and a denial returns `null`. If you don't declare it, no permission is needed. |
| Android | `Front` and `Back` are best effort. Android has no standard extra to choose the camera, so FileKit sends the extras that common camera apps read. Some devices ignore them. |
| iOS | Add `NSCameraUsageDescription` to your `Info.plist`: iOS terminates apps that open the camera without it. |
| iOS | The photo is saved as a full-quality JPEG. A missing camera (such as the Simulator) or an unavailable `Front` or `Back` camera fails with a `FileKitDialogException`. |

## Android setup

<AndroidFileProviderSetup />

For example, to save to app-specific external storage:

```kotlin androidMain
val externalDir = PlatformFile(FileKit.context.getExternalFilesDir(null)!!)

val photo = FileKit.openCameraPicker(
    destinationFile = externalDir / "photo.jpg",
    openCameraSettings = FileKitOpenCameraSettings(
        authority = "${FileKit.context.packageName}.fileprovider",
    ),
)
```

With Compose, pass the same `openCameraSettings` to `rememberCameraPickerLauncher` and the file to `launch(destinationFile = ...)`.

`openFilePicker` shows the platform's native file dialog and returns the selected file as a `PlatformFile`, or a list of files in multiple mode.

## Usage

<CodeGroup>

```kotlin Compose
val launcher = rememberFilePickerLauncher(
    onError = { failure -> showError(failure.message) },
) { file ->
    // file is a PlatformFile, or null when the user cancelled
}

Button(onClick = { launcher.launch() }) {
    Text("Pick a file")
}
```

```kotlin Suspend API
val file: PlatformFile? = FileKit.openFilePicker()
```

</CodeGroup>

## Options

In Compose, pass these options to `rememberFilePickerLauncher`. `launch()` takes no arguments.

<ResponseField name="type" type="FileKitType" default="File()">
  Which files the user can pick. `File()` allows any file.

  <Expandable title="values">
    <ResponseField name="File(extensions)" type="FileKitType">
      Files with the given extensions, without the dot: `FileKitType.File("pdf", "docx")`. See [Filter by extension](#filter-by-extension).
    </ResponseField>
    <ResponseField name="Image, Video, ImageAndVideo" type="FileKitType">
      Media files. Opens the native [gallery picker](/dialogs/gallery-picker) on Android and iOS, and a filtered file dialog elsewhere.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="mode" type="FileKitMode" default="Single">
  How many files the user can pick. The result type follows the mode.

  <Expandable title="values">
    <ResponseField name="Single" type="PlatformFile?">
      One file.
    </ResponseField>
    <ResponseField name="Multiple(maxItems)" type="List<PlatformFile>?">
      Several files. `maxItems` is `1` to `50`, or `null` for no limit. See [Pick multiple files](#pick-multiple-files).
    </ResponseField>
    <ResponseField name="SingleWithState, MultipleWithState(maxItems)" type="FileKitPickerState">
      Reports progress while picked files are prepared. The suspend API returns a `Flow`. See [Track progress](#track-progress).
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="directory" type="PlatformFile?" default="null">
  Folder the dialog opens in. Ignored on Android and the web.
</ResponseField>

<ResponseField name="dialogSettings" type="FileKitDialogSettings" default="createDefault()">
  Title, parent window, and other [per-platform settings](/dialogs/dialog-settings).
</ResponseField>

## Filter by extension

Pass the extensions without the dot:

<CodeGroup>

```kotlin Compose
val launcher = rememberFilePickerLauncher(
    type = FileKitType.File("pdf", "docx"),
    onError = { failure -> showError(failure.message) },
) { file ->
    // a pdf or docx file, or null
}
```

```kotlin Suspend API
val file = FileKit.openFilePicker(type = FileKitType.File("pdf", "docx"))
```

</CodeGroup>

`FileKitType.File` also accepts a `List<String>` or a `Set<String>`.

## Pick multiple files

`FileKitMode.Multiple()` returns a `List<PlatformFile>`, or `null` when the user cancels:

<CodeGroup>

```kotlin Compose
val launcher = rememberFilePickerLauncher(
    mode = FileKitMode.Multiple(maxItems = 10),
    onError = { failure -> showError(failure.message) },
) { files ->
    // List<PlatformFile>? with at most 10 files
}
```

```kotlin Suspend API
val files = FileKit.openFilePicker(mode = FileKitMode.Multiple(maxItems = 10))
```

</CodeGroup>

The iOS gallery picker and the Android Photo Picker enforce `maxItems` in their UI. Other dialogs, including Android's document picker fallback, have no native limit, so FileKit keeps the first `maxItems` files in the order the platform returns them.

## Track progress

`SingleWithState` and `MultipleWithState` report each step as a `FileKitPickerState`, which lets you show a loading indicator while large files are prepared. In Compose, each state reaches `onResult`. The suspend API returns a `Flow`:

```kotlin
FileKit.openFilePicker(mode = FileKitMode.MultipleWithState()).collect { state ->
    when (state) {
        is FileKitPickerState.Started -> showLoading(total = state.total)
        is FileKitPickerState.Progress -> updateLoading(state.processed.size, state.total)
        is FileKitPickerState.Completed -> showFiles(state.result)
        is FileKitPickerState.Failed -> showError(state.cause.message)
        FileKitPickerState.Cancelled -> hideLoading()
    }
}
```

Progress matters most for iOS gallery picks, where FileKit copies each item before returning it. Other dialogs deliver every state at once when they close. See [Results and errors](/dialogs/error-handling#state-tracking-picker-modes) for the full state contract.

## Platform notes

| Platform | Behavior |
| --- | --- |
| Android | Storage Access Framework document picker. Extensions are converted to MIME types: unknown extensions are dropped, and if none is known every file is allowed. |
| iOS | `UIDocumentPickerViewController`. Media types open `PHPickerViewController`. |
| macOS | `NSOpenPanel`. |
| JVM | `NSOpenPanel` on macOS, `IFileDialog` on Windows, and the XDG Desktop Portal on Linux, with an AWT/Swing fallback when no portal runs. |
| Linux native | XDG Desktop Portal only, with no fallback dialog. Dialog settings support the title only. See [Linux setup](/dialogs/setup#linux-setup). |
| Windows native | `IFileDialog`. Dialog settings support the title only. |
| Web | `<input type="file">`. The type filter becomes the `accept` attribute. `directory` and dialog settings are ignored. |

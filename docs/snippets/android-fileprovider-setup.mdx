Only needed for files outside `FileKit.filesDir` and `FileKit.cacheDir`. `filekit-dialogs` already ships a FileProvider (`${applicationId}.FileKitFileProvider`) that covers those two directories, and `content://` files returned by the pickers need no provider at all. For any other location, such as `getExternalFilesDir()`, `FileProvider` throws an `IllegalArgumentException` until you declare your own provider.

<Steps>
  <Step title="Declare a provider in your manifest">
    ```xml AndroidManifest.xml
    <provider
        android:name="androidx.core.content.FileProvider"
        android:authorities="${applicationId}.fileprovider"
        android:exported="false"
        android:grantUriPermissions="true">
        <meta-data
            android:name="android.support.FILE_PROVIDER_PATHS"
            android:resource="@xml/file_paths" />
    </provider>
    ```
  </Step>
  <Step title="List the directories it may expose">
    Add one entry per location you use, for example app-specific external storage:

    ```xml res/xml/file_paths.xml
    <paths>
        <external-files-path name="external_files" path="." />
    </paths>
    ```

    See [FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider) for every path type.
  </Step>
  <Step title="Pass the authority to FileKit">
    The `authority` parameter exists only on Android, so build these settings in `androidMain`:

    ```kotlin androidMain
    val authority = "${FileKit.context.packageName}.fileprovider"

    FileKitOpenCameraSettings(authority = authority) // camera picker
    FileKitShareSettings(authority = authority) // share file
    FileKitOpenFileSettings(authority = authority) // open with default app
    ```
  </Step>
</Steps>

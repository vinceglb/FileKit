This guide opens a native file picker, reads the selected file, and saves a new file to a location the user chooses.

<Steps>
  <Step title="Add the dependency">
    <VersionDialogs/>

    Both artifacts include `filekit-core`. For Compose apps, add `filekit-dialogs-compose`. To call the dialogs from ViewModels or non-Compose code, `filekit-dialogs` is enough. See [Installation](/installation) for every module.
  </Step>

  <Step title="Initialize FileKit where needed">
    Most targets work without setup. Android (without Compose), desktop JVM, and Linux or Windows native need one line at startup.

    <Tabs>
      <Tab title="Android">
        With `filekit-dialogs-compose`, nothing to do.

        With `filekit-dialogs` only, register your activity so FileKit can launch dialogs:

        ```kotlin MainActivity.kt
        class MainActivity : ComponentActivity() {
            override fun onCreate(savedInstanceState: Bundle?) {
                super.onCreate(savedInstanceState)
                FileKit.init(this)
            }
        }
        ```
      </Tab>
      <Tab title="JVM desktop">
        Give FileKit your application ID before showing UI. It is used for the app's files and cache directories.

        ```kotlin main.kt
        fun main() {
            FileKit.init(appId = "com.example.myapp")

            application {
                Window(onCloseRequest = ::exitApplication) { App() }
            }
        }
        ```

        On Linux, packaged apps also need the `jdk.security.auth` module. See [Dialogs setup](/dialogs/setup#linux-setup).
      </Tab>
      <Tab title="Linux & Windows native">
        ```kotlin main.kt
        fun main() {
            FileKit.init(appId = "com.example.myapp")
        }
        ```

        On Linux, dialogs use the XDG Desktop Portal and link against `libdbus-1`. See [Dialogs setup](/dialogs/setup#linux-setup).
      </Tab>
      <Tab title="iOS, macOS, JS, Wasm">
        Nothing to do. FileKit works out of the box.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Pick a file">
    <CodeGroup>

    ```kotlin Compose
    val launcher = rememberFilePickerLauncher(
        onError = { failure -> println("Picker failed: ${failure.message}") },
    ) { file ->
        // file is a PlatformFile, or null when the user cancelled
        println("Picked ${file?.name}")
    }

    Button(onClick = { launcher.launch() }) {
        Text("Pick a file")
    }
    ```

    ```kotlin Suspend API
    // Call from a coroutine: a ViewModel, a LaunchedEffect, a click handler with scope.launch...
    val file: PlatformFile? = FileKit.openFilePicker()
    println("Picked ${file?.name}")
    ```

    </CodeGroup>

    Restrict the selection with `type = FileKitType.Image`, `FileKitType.Video`, or `FileKitType.File(extensions = listOf("pdf"))`. Pick several files with `mode = FileKitMode.Multiple()`. See [File picker](/dialogs/file-picker) for all options.
  </Step>

  <Step title="Read it">
    `PlatformFile` exposes the same read API on every platform:

    ```kotlin
    val name: String = file.name
    val size: Long = file.size()

    val text: String = file.readString()
    val bytes: ByteArray = file.readBytes()
    ```

    For an image in Compose, call `file.toImageBitmap()` or use the [Coil integration](/integrations/coil).
  </Step>

  <Step title="Save a file">
    Ask the user where to save, then write to the returned file:

    <CodeGroup>

    ```kotlin Compose
    val scope = rememberCoroutineScope()
    val saver = rememberFileSaverLauncher(
        dialogSettings = FileKitDialogSettings.createDefault(),
        onError = { failure -> println("Saver failed: ${failure.message}") },
    ) { file ->
        scope.launch { file?.writeString("Hello FileKit!") }
    }

    Button(onClick = { saver.launch(suggestedName = "hello", defaultExtension = "txt") }) {
        Text("Save")
    }
    ```

    ```kotlin Suspend API
    val file = FileKit.openFileSaver(suggestedName = "hello", defaultExtension = "txt")
    file?.writeString("Hello FileKit!")
    ```

    </CodeGroup>

    <Note>
      The file saver is available on Android, iOS, macOS, JVM, and Linux and Windows native, so call it from a non-web source set. Browsers don't let you choose a save location, so on JS and Wasm use `FileKit.download(bytes, fileName)` instead. See [Files on the web](/core/web#download-files).
    </Note>
  </Step>
</Steps>

That's a complete round trip. FileKit uses each platform's native dialog, so the picker looks and behaves the way your users expect.
